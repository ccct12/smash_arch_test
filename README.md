# SMASH ARCH

전국 건축사사무소 사옥을 부수고, 구별로 정복하는 3D 웹 게임입니다. 회사와 관계없는 비공식 팬 게임이에요.
원작 아이디어는 SMASH HYU에서 얻었고, 코드는 새로 작성했어요.

## 파일 구성

| 파일 | 하는 일 |
|---|---|
| `index.html` | 화면과 시작 코드. 구글 시트에서 사무소 목록을 받은 뒤 `game.js`를 실행해요 |
| `game.js` | 게임 본체 (3D 렌더링, 파괴, 단면, 랭킹, 구별 정복) |
| `config.js` | **배포 전에 고칠 파일.** Apps Script 웹앱 주소를 넣어요 |
| `data/firms.json` | 시트 연결이 안 될 때 쓰는 사무소 목록 스냅샷 (2026-10-31 기준 9,456곳) |
| `tools/build_tiles.py` | 지도 타일 만드는 스크립트 (GitHub Actions가 실행) |
| `.github/workflows/` | `build-tiles.yml`(지도 타일 만들기) · `deploy.yml`(사이트 배포) |
| `apps-script/Api.gs` | 구글 시트에 넣을 서버 코드 (사무소 목록 · 랭킹 · 정복 기록). GitHub에는 올라가도 상관없지만 실행은 시트에서 해요 |

## 1. 구글 시트에 서버 코드 넣기

1. `건축사사무소_좌표작업` 시트를 열고 **확장 프로그램 → Apps Script**를 엽니다.
2. 왼쪽 파일 목록의 **+ → 스크립트**로 새 파일을 만들고 이름을 `Api`로 지정한 뒤, `apps-script/Api.gs` 내용을 붙여넣고 저장합니다.
   - 같은 프로젝트에 예전 `Ranking.gs`가 있으면 지워주세요. `doGet`이 겹치면 배포가 꼬여요.
   - `Geocode.gs`는 그대로 두세요. `Api.gs`의 함수·변수는 `sa`로 시작하게 이름을 붙여 겹치지 않게 했어요. 다만 `Geocode.gs`에 `doGet`이나 `doPost`가 있다면 하나만 남겨야 해요.
3. 위쪽 함수 선택에서 `testSmashApi`를 고르고 **실행**합니다. 처음 한 번은 권한 승인 창이 떠요. 실행 기록에 "사무소 9456곳"이 보이면 정상이에요.
4. **배포 → 새 배포 → 유형: 웹 앱**
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
5. 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.

시트에는 `랭킹`, `철거` 탭이 처음 쓸 때 자동으로 생겨요.
예전에 따로 만든 랭킹 시트가 있었다면, 그 시트의 `랭킹` 탭 내용을 이 시트의 `랭킹` 탭으로 복사하면 기록이 이어져요.

## 2. 사이트 설정

`config.js`를 열어 `API_URL`에 복사한 웹앱 주소를 넣습니다.

```js
window.SMASH_CONFIG = {
  API_URL: 'https://script.google.com/macros/s/여기에_복사한_ID/exec'
};
```

## 3. GitHub Pages로 배포

1. GitHub에서 새 저장소를 만듭니다 (예: `smash-arch`, Public).
2. **Add file → Upload files**로 이 폴더 안의 파일을 폴더 구조 그대로 올립니다. (`index.html`이 저장소 맨 위에 있어야 해요)
3. 저장소 **Settings → Pages → Build and deployment**에서 Source를 **GitHub Actions**로 바꿉니다.
   - 예전처럼 "Deploy from a branch"로 두면 지도 타일이 붙지 않아요.
4. 파일을 올리면 **Actions** 탭에서 `사이트 배포`가 자동으로 돌고, 1~2분 뒤 `https://<GitHub 아이디>.github.io/smash-arch/` 에서 열려요.

## 4. 지도 타일 (첫 화면을 빠르게)

공용 지도 서버(Overpass)는 붐비면 수십 초씩 걸려서, 사무소 주변 지도를 미리 만들어 사이트에 같이 올려요.

1. **Actions → 지도 타일 만들기 → Run workflow**를 누릅니다. (처음 한 번. 이후 매월 2일 새벽에 자동으로 갱신)
2. 한국 OSM 파일(Geofabrik)을 받아 사무소 주변 750m만 잘라 `tiles/`를 만들고, 릴리스 `tiles-latest`에 `tiles.tar`로 올려요. 보통 20~60분 걸려요.
3. 끝나면 `사이트 배포`가 이어서 돌면서 타일을 사이트에 붙여요. 사이트의 `tiles/meta.json`이 열리면 성공이에요.

- 게임은 미리 만든 타일 → 브라우저 저장본 → 공용 서버 순서로 찾아요. 타일 범위 밖(멀리 축소하거나 목록에 없는 주소)만 공용 서버에 물어봐요.
- 범위를 바꾸려면 Run workflow에서 반경(m)을 고치면 돼요. 넓힐수록 용량이 커져요 (GitHub Pages는 사이트 1GB까지).
- 릴리스 `tiles-latest`는 워크플로가 관리하니 지우지 마세요. 지우면 다음 배포부터 타일 없이 공용 서버만 써요.

## 시트와 게임이 이어지는 방식

- 게임을 열면 웹앱의 `?action=firms`에서 사무소 목록(사무소명·주소·좌표·시도·시군구)을 받아요. 메모·검증 칸과 시트 자체는 공개되지 않아요.
- 한 번 받은 목록은 브라우저에 저장해 두고 바로 시작한 뒤, 뒤에서 새 목록을 받아 **다음 접속 때** 반영해요.
- 서버 쪽 캐시가 10분이라, 시트를 고치면 최대 10분 뒤 새 목록이 나가요.
- 웹앱에 연결이 안 되면 `data/firms.json` 스냅샷으로 시작해요.
- **시트의 행 순서와 번호를 바꾸지 마세요.** 회사키가 `d` + (번호 − 1)이라, 번호가 바뀌면 공유 링크와 랭킹·정복 기록이 다른 사무소를 가리켜요. 새 사무소는 맨 아래에 다음 번호로 추가하면 돼요.

## 게임 요소

- **랭킹**: 이번 주 가장 많이 부서진 사무소 TOP 10, 개인 최고 점수 TOP 10 (`랭킹` 탭)
- **구별 정복**: 사옥이나 동네 핀의 건축사무소 건물을 무너뜨리면 그 사무소가 "철거됨"으로 기록돼요.
  - **나**: 이 브라우저에 저장된 내 기록
  - **모두 함께**: 모든 플레이어 기록을 합친 값 (`철거` 탭, 사무소당 한 줄)
  - 서울 25개 구 타일 지도와 전국 시도 → 시군구 막대로 보여주고, 구를 누르면 아직 안 부순 사무소로 바로 출동할 수 있어요.
  - 진행도는 **좌표가 있는 사무소 기준**이에요. 좌표 작업 전인 구는 "준비 중"으로 보이고, 시트에서 좌표를 채우면 자동으로 열려요.

## 알려둘 점

- 누구나 점수와 철거 기록을 보낼 수 있는 구조라 조작을 완벽히 막지는 못해요. 이상한 기록은 시트에서 행을 지우면 돼요.
- 지도 타일 범위 밖은 무료 공용 OpenStreetMap(Overpass) 서버를 써서, 처음 가는 지역은 10~30초 걸릴 수 있어요. 한 번 받은 지역은 브라우저에 저장돼 다음부터 바로 떠요.
- 코드를 고친 뒤 Apps Script는 **배포 → 배포 관리 → 수정 → 버전: 새 버전**으로 다시 배포해야 반영돼요. (웹앱 주소는 그대로예요)
